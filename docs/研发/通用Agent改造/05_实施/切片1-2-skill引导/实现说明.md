## 设计决策（V1，刻意从简）

1. **召回不打分排序之外任何状态**：词项匹配 = 消息文本 vs name/description/tags/triggers 的 token 交集；name 命中 +5、tags/triggers +2/个、description +1/个。高置信 = 最高分 >0 且 ≥ 次高分 ×2；否则视为近似多候选，**不绑定只记录**（V1 无 LLM 选择器）。
2. **预算截断**：按分数降序贪心，超过 `max_count` 或正文 token 合计超 `token_budget` 即停止；首个候选就超 token 预算 → `reason="budget_limited"`、绑定为空（安全降级，不阻塞原 Runner）。
3. **activation 解析**：显式 `activation` 字符串（nanobot metadata > 顶层）→ `always`/`manual`/`disabled` 布尔 → 默认 `auto`；`disabled_skills` 配置仍先行过滤。`always` 不参与自动候选（其语义由 `build_system_prompt` 内部保留）。
4. **合并规则**：`$skill` 显式 > 自动绑定；自动绑定在 `recall_skill_candidates(exclude=显式名)` 中已排除显式项，`build_messages` 内再兜底去重。
5. **观测**：`observe_lane=True` 时对每条进入 build 的消息（含 SYSTEM/other）写一条结构化日志：`lane / explicit / candidates / bound / reason / preview(≤200字)`，不落会话历史。两个 flag 全关时 `_decide_skill_lane` 与 `_observe_lane` 均不被调用——零新增计算、零日志、零注入。

## 实现决策补充（评审后修订）

- 高置信判定：最高分 ≥ 次高分×2 **或** 最高分有 name 命中而次高分无 name 命中（name 命中是强信号，不被偶然的描述词命中否决）。
- 观测日志的 `preview` 遵循 `session.policy.log_content`：会话选择隐藏内容时写 `[content hidden]`。
- CJK 词项匹配含 bigram（`视觉` 可命中 `视觉设计`）。
