# 模型参与与契约走纸测试

**状态：** 设计验证材料；尚未接入运行时代码

**日期：** 2026-08-10

**关联：** [模型输入输出契约](../03_方案/模型输入输出契约.md)、[轻量优先执行规划技术设计](../03_方案/轻量优先执行规划技术设计.md)、ADR-009

## 1. 目的

本材料不模拟模型“聪不聪明”，只验证输入边界、调用次数、状态写入和降级是否符合三车道基准。所有 JSON 均为字段示意，`…` 代表受配置约束的截断，而不是省略了未授权上下文。

## 2. 场景 A：自包含问答

**用户：** “什么是 MCP？”

| 步骤 | 参与者 | 输入 | 输出 / 状态 |
| --- | --- | --- | --- |
| 1 | AdmissionGate | 当前消息；无待澄清、无任务帧。 | 代码判定为自包含问答，不调用 IntentResolver。 |
| 2 | skill 本地召回 | 当前消息与 descriptor 索引。 | 无高价值候选，不调用 SkillSelector。 |
| 3 | 原 Runner | 原有 system prompt、历史、工具定义、当前消息。 | 产生回答；保持原有保存与响应。 |

**LLM 调用：** 仅原 Runner 1 次。不得创建 `orchestration.v1` metadata、TaskFrame、ExecutionPlan、WebUI 编排事件或独立结构化调用。

## 3. 场景 B：明确单步骤外部动作

**上下文：** 当前会话有一份用户已确认的邮件草稿及收件人。

**用户：** “继续，把这封邮件发给王丽。”

| 步骤 | 参与者 | 输入 | 输出 / 状态 |
| --- | --- | --- | --- |
| 1 | AdmissionGate | 当前消息 + 唯一明确任务锚点。 | 代码直接锚定；不调用 IntentResolver。 |
| 2 | skill 选择 | 若本地命中唯一邮件工作流 skill，则直接绑定正文。 | 不调用 SkillSelector。 |
| 3 | 原 Runner | 既有完整执行上下文 + 可选绑定 skill 正文。 | 按当前工具权限执行发送或报告权限/能力失败。 |

**LLM 调用：** 仍是原 Runner 的既有工具循环；不调用 Planner、不创建 subagent、不因“发邮件”新增确认，也不建立持久任务图。

## 4. 场景 C：无对象的“继续”

**上下文：** 没有 TaskFrame、ClarificationState、明确引用、附件或唯一未完成事项。

**用户：** “继续。”

```text
AdmissionGate 输入事实：
  current.text = "继续。"
  awaiting_clarification = null
  candidate_tasks = []
  admissible_evidence = []
```

此场景由代码直接判定无可推进对象，使用模板追问“你希望我继续哪一项？请给出任务、对象或引用。”

**LLM 调用：** 0 次。不得为了寻找任务调用工具、读取历史、启动 subagent 或运行普通 Runner。用户输入与澄清问题通过 `finish_non_execution_turn` 保存。

## 5. 场景 D：两个无关事项的“继续”

**上下文：** 同一会话有两个 active TaskFrame：

- `task:report`：完成季度报告；
- `task:travel`：预订北京行程。

**用户：** “继续。”

```json
{
  "contract": "admission",
  "data": {
    "current": {"text": "继续。", "attachment_refs": [], "explicit_reference_ids": []},
    "candidate_tasks": [
      {"id": "task:report", "status": "ready", "goal": "完成季度报告", "scope_summary": "…", "acceptance_summary": "…", "relation_summary": "无关联"},
      {"id": "task:travel", "status": "ready", "goal": "预订北京行程", "scope_summary": "…", "acceptance_summary": "…", "relation_summary": "无关联"}
    ],
    "admissible_evidence": []
  }
}
```

**期望 IntentResolver 输出：**

```json
{
  "disposition": "clarify",
  "missing_fields": ["choice"],
  "clarification_question": "你要继续完成季度报告，还是预订北京行程？",
  "evidence_ids": []
}
```

代码必须验证该输出没有擅自选择 `task:report` 或 `task:travel`。通过后只持久化 ClarificationState，不调用 skill、Planner、Runner、工具或 subagent。

**LLM 调用：** IntentResolver 最多 1 次；失败时以代码模板列出两个任务，仍然 0 工具调用。

## 6. 场景 E：30 个 skill 中的近似候选

**用户：** “把这段调研资料整理成一篇适合微信公众号发布的文章。”

**本地召回：** `gzh-copywriter`、`knowledge-expression`、`content-blog` 三者分数接近；其余 27 个不进入模型候选。

```json
{
  "contract": "skill_selection",
  "data": {
    "task": {"goal": "将调研资料整理为公众号文章", "scope": "用户提供的资料", "constraints": [], "anchor_evidence_ids": ["current_message"]},
    "current_request": "把这段调研资料整理成一篇适合微信公众号发布的文章。",
    "explicit_skill_names": [],
    "candidates": [
      {"name": "gzh-copywriter", "description": "基于项目材料撰写微信公众号推文", "source": "workspace", "optional_tags": ["公众号"], "optional_triggers": [], "availability": "available"},
      {"name": "knowledge-expression", "description": "将知识与项目材料转成可追溯的文章草稿", "source": "workspace", "optional_tags": ["知识库"], "optional_triggers": [], "availability": "available"},
      {"name": "content-blog", "description": "生成长文并保持品牌一致性", "source": "workspace", "optional_tags": ["文章"], "optional_triggers": [], "availability": "available"}
    ],
    "selection_budget": {"max_count": "configured", "max_context_tokens": "configured"}
  }
}
```

SkillSelector 只能输出候选名，例如：

```json
{"decision": "bind", "selected_names": ["gzh-copywriter"], "reason_codes": ["workflow_match"]}
```

代码读取该 skill 正文并传给原 Runner；三个 skill 的完整正文、其余 27 个 skill 正文、MCP/tool schema 都不会出现在选择器输入。

**LLM 调用：** SkillSelector 1 次 + 原 Runner 正常调用；若本地高置信直接命中，则前者为 0。

## 7. 场景 F：多源调研、并行收集、最终汇总

**用户：** “比较三个竞品的定价、核心功能和近期动态，给我一份推荐方案。”

### 7.1 PlanInput

```json
{
  "contract": "plan",
  "data": {
    "task": {
      "id": "task:competitor-review",
      "goal": "比较三个竞品并给出推荐",
      "scope": "定价、核心功能、近期动态",
      "constraints": ["列出来源", "输出推荐理由"],
      "acceptance": ["三家均覆盖", "比较维度完整"],
      "evidence_ids": ["current_message"]
    },
    "selected_skills": [],
    "execution_facts": {
      "subagent_enabled": true,
      "max_concurrent_subagents": "configured",
      "background_requested": false,
      "declared_resource_claims": [{"resource": "web", "mode": "read"}]
    }
  }
}
```

Planner 可以提出三个只读子节点；面向用户的最终汇总不作为重复的 parent 节点，而由 JoinResponder 负责。Planner 不能创建真正 ID、不能调用搜索工具、不能要求未声明权限。协调器验证无共享写冲突、并发配额及依赖后，才预留 RouteReceipt 并启动子节点。

### 7.2 NodeExecutionContext

每个子节点只收到自己的竞品、比较维度、交付物、验收与必要来源约束；不会收到父会话全文或另外两个子节点的中间结果。主汇总节点收到已完成节点的受限结果引用。

### 7.3 PlanJoinInput

当三个子节点均由协调器确认为当前 `plan_id` 的 `completed` 后，才构造：

```json
{
  "contract": "plan_join",
  "data": {
    "task": {"goal": "比较三个竞品并给出推荐", "scope": "定价、核心功能、近期动态", "acceptance": ["三家均覆盖"], "user_requested_delivery": "当前回合"},
    "plan": {"id": "plan:opaque", "delivery_mode": "join_now", "required_node_ids": ["node:a", "node:b", "node:c"]},
    "node_outcomes": [
      {"node_id": "node:a", "actor": "subagent", "status": "completed", "deliverable": "竞品 A 资料", "acceptance": "覆盖三维度", "result_excerpt_or_artifact_ref": "…"},
      {"node_id": "node:b", "actor": "subagent", "status": "completed", "deliverable": "竞品 B 资料", "acceptance": "覆盖三维度", "result_excerpt_or_artifact_ref": "…"},
      {"node_id": "node:c", "actor": "subagent", "status": "completed", "deliverable": "竞品 C 资料", "acceptance": "覆盖三维度", "result_excerpt_or_artifact_ref": "…"}
    ]
  }
}
```

JoinResponder 无工具，只输出 `complete/incomplete + final_answer`。任何一个节点失败、取消、跨 session、跨 plan 或 receipt 不匹配时，协调器不允许 `complete`，也不会把此前主 agent 的候选终答提前流式展示。

**LLM 调用：** Planner 1 次；各节点按既有 Runner/subagent 调用；JoinResponder 1 次。它们是复杂任务的可见成本，不能出现在场景 A-C。

## 8. 走纸结论

| 核验点 | 结果 |
| --- | --- |
| 普通路径是否新增固定 LLM 往返 | 否；场景 A、B 仅原 Runner，场景 C 为 0。 |
| 所有 LLM 输入是否拥有足够任务信息 | 是；每层只拿完成其职责必需的受控数据，不靠全文 history 猜测。 |
| 是否把权限或工具选择交给新层 | 否；所有结构化调用无工具，最终执行继续由现有 Runner/ToolRegistry 决定。 |
| 是否能阻断跨计划 / 跨会话结果 | 是；JoinInput 只能由经 RouteReceipt 校验后的节点结果构建。 |
| 是否仍有待实测项 | 有；模型 JSON 遵从性、中文 skill 召回、token/时延和真实任务成功率必须在隔离环境回放。 |
