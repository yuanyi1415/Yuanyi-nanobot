# 通用 Agent 改造资料库

本目录是本私有仓库中“将 nanobot 演进为通用型 Agent”的研发事实源。它服务设计、实现、评测与复盘，不替代 `docs/` 下的公开使用文档，也不改变运行时配置。

## 当前主题

首个主题为“上下文优先的意图理解与 subagent 调度”。目标不是增加一个关键词分类器，而是在任何工具调用或委派前，先判断当前上下文中是否存在可解释、可追溯的任务对象或任务图。

## 目录与职责

| 位置 | 内容 | 何时创建/更新 | 事实地位 |
| --- | --- | --- | --- |
| `00_项目/` | 目标、范围、版本边界 | 范围或阶段改变时 | 当前项目边界 |
| `01_需求/` | 已确认需求、业务规则、验收标准 | 用户确认需求时 | 产品行为事实源 |
| `02_调研/` | 代码现状、外部产品、实验与证据 | 结论依赖调查时 | 证据来源，不直接替代需求 |
| `03_方案/` | 可比较的产品/技术方案草案 | 方案具备问题、候选与取舍时 | 草案，须引用需求与证据 |
| `04_评测/` | 对话样本、预期行为、回放结果、指标 | 开始验证行为时 | 验证事实源 |
| `05_实施/` | 实施切片、变更说明、测试记录、迁移说明 | 开始开发后 | 交付追踪 |
| `06_决策记录/` | 已确认且会约束后续工作的决策（ADR） | 做出不可随意反转的选择时 | 决策事实源 |

目录只在出现实际内容时创建；不预建空文件或空目录。

## 文档治理规则

1. **先分层，后下结论。** 文档中的内容必须标为“事实/证据、已确认决策、假设、未决问题”之一；不能把推测写成事实。
2. **需求优先于方案。** `01_需求` 说明“必须怎样表现”；`03_方案` 说明“可以怎样实现”。方案不能悄悄修改需求。
3. **ADR 只追加或废止，不静默改写。** 如果决策变化，新建后续 ADR，明确“替代 ADR-xxx”的原因与生效范围。
4. **过程材料保留结论与证据，不复制整段聊天。** 每条确认决策记录来源、日期、影响与关联文件；敏感原文和无关闲聊不入库。
5. **评测是发布门。** 对话行为变更必须先有 `04_评测` 中的场景与预期，再记录回放结果；不能只用“模型看起来会做”作为验收。
6. **实施必须可追踪。** 代码变更、测试和用户可见行为，必须反向链接到 `FR-xxx`、`AC-xxx` 与 ADR；未覆盖项明确标为未完成。
7. **版本化而非覆盖历史。** 需求或方案发生实质变化时升版本并保留简短变更记录；已确认的旧版本保留其适用范围。
