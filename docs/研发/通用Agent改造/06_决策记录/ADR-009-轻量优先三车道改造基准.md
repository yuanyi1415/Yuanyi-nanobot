# ADR-009：轻量优先三车道改造基准

**状态：** 已确认  
**日期：** 2026-08-10  
**决策者：** 用户  
**关联：** [意图理解与调度需求 v0.8](../01_需求/意图理解与调度需求.md)、[主流 Agent 技能机制对比](../02_调研/主流Agent技能机制对比.md)

## 背景

本次改造的目标，是让 nanobot 更主动地使用 skill 与 subagent，同时保留其作为轻量、直接工具的使用体验。此前桥接草案将独立意图调用、计划生成和持久任务图作为普通 `ready` 回合的默认路径，会为简单任务引入额外模型往返、状态和用户可见编排噪音。

轻量体验是本项目不可牺牲的产品资产；主动性必须只在能证明收益的场景介入。

## 决策

后续所有方案、实现、评测和灰度均以“**轻量优先、三车道、快速路径零侵入**”为最高基准。

### 三车道

| 车道 | 适用条件 | 允许新增能力 | 明确禁止 |
| --- | --- | --- | --- |
| 快速车道 | 问答、唯一单步骤动作、无依赖且无需后台续办 | 受控任务锚定；命中时绑定少量 skill | 独立 Planner 调用、subagent、持久任务图、编排噪音 |
| skill 引导车道 | 明确命中可提升质量/稳定性的 skill | 注入最终绑定 skill 正文，继续复用原生 Runner | 全量 skill 正文注入、改变工具/MCP 权限语义 |
| 编排车道 | 多目标、依赖、可并行、后台或跨回合收益明确 | ExecutionPlan、计划 subagent、结果收据、汇合与终答门 | 无收益的拆分、无边界 spawn、跨会话结果投递 |

### 不变量

1. 意图识别是工具执行前的逻辑准入，不等于每轮都要增加独立 LLM 调用；快速车道不得新增独立模型往返。
2. 所有 active skill 默认参与自动候选；全文只在最终绑定时按需加载。`manual`、`disabled` 和 `always` 是用户显式设置的例外，不是默认。
3. skill 是工作流提示，不是权限来源；其声明不改变现有 ToolRegistry、MCP、账号、策略或确认机制。
4. subagent 是有收益的执行资源，不是默认工作者。只有输入、边界、验收、独立性和资源收益明确的节点才可委派。
5. 普通 tool/MCP 不进入独立推荐加载体系，仍由既有 Runner 在执行时选择和调用。
6. 简单任务只保留当回合锚点；TaskFrame、ExecutionPlan、ResultRouteReceipt 等持久状态仅在跨回合、后台或编排车道中创建。
7. feature flag 关闭时，调用次数、Runner、工具、权限、memory、会话和用户可见行为必须保持当前基线。

## 后果

### 保留

- 上下文优先的任务锚定；
- skill 索引与按需正文加载；
- 复杂任务的执行图、受控 subagent、会话/计划隔离与终答门；
- 原生 Runner、ToolRegistry、MCP、权限、memory 和会话机制。

### 暂停或移出第一阶段

- 每条普通消息的独立 Intent LLM；
- 每个 `ready` 任务的独立 Planner；
- 所有任务的持久化 TaskFrame/完整状态机；
- MCP/tool 全局推荐器；
- 固定 subagent 角色体系；
- 节点级动态 ToolRegistry 重建；
- 完整第三方 skill 市场、签名和扫描体系。

### 必须补齐后才能重新进入开发

1. 四类输入契约：`IntentInput`、`SkillSelectionInput`、`PlanInput`、`NodeExecutionInput`；
2. 快速/skill/编排车道的确定分流条件；
3. 30 个 active skill 下的候选选择、冲突处理、正文预算和加载可观测性；
4. subagent 收益门槛与复杂任务判定；
5. 基于真实回放的 token、缓存、时延、skill 命中和委派收益评测；
6. Provider 对“意图控制与工具调用”物理实现方式的兼容性验证。

## 对既有决策的关系

本 ADR 保留 ADR-001 至 ADR-006 的任务锚定、权限边界和会话隔离原则；保留 ADR-007、ADR-008 中与兼容、结果隔离和终答真实性相关的约束。

本 ADR 替代此前方案中“所有 `ready` 回合默认独立意图与计划调用、所有可推进任务默认建立执行图”的实施前提。`执行图最小桥接方案 v0.3` 仅作为历史正确性材料，不得据此进入开发。

## 验证与发布门

新方案的回放必须至少证明：

1. 快速车道不增加独立 LLM 往返，且不创建编排状态；
2. 无 skill 命中时不注入 skill 正文；
3. skill 命中能在成功率、稳定性或必要流程遵循上带来可测收益；
4. subagent 仅在复杂任务中启用，并在成功率、时延或主上下文压力上优于主 agent 基线；
5. 计划模式保持跨会话、跨计划和重复结果零泄漏；
6. feature flag 关闭时的回放与当前 nanobot 基线一致。
