# ADR-002：任务准入与状态迁移架构

**状态：** 已接受  
**日期：** 2026-08-09  
**决策者：** 用户确认，研发负责整理  
**关联需求：** FR-001 至 FR-009；AC-001 至 AC-006  
**关联决策：** ADR-001

## 背景

ADR-001 已规定：自然语言任务在规划、工具调用和 subagent 调度前，必须先获得可解释的任务对象或任务图执行前沿。

现有 nanobot 的普通消息由 `AgentLoop` 直接进入主模型—工具循环；上下文机制能提供会话、记忆、引用和运行时信息，但没有独立记录本轮任务理解、状态转换和准入理由。

本决策要回答的是：意图理解应采用何种架构，而不是为所有用户表达建立无限增长的分类标签。

## 选项

### 选项 A：固定意图分类器驱动执行

- **做法：** 将消息分类为“问答、研究、写作、开发、执行”等，再将类别映射到工具或 subagent 角色。
- **优点：** 实现表面简单，便于统计类别。
- **缺点：** 通用任务类别无限；无法可靠处理省略指代、跨轮续办、任务依赖和授权边界；类别会被误用为执行许可。
- **结论：** 不采用。

### 选项 B：主 agent 自由解释消息并决定执行

- **做法：** 继续主要依赖系统提示词和主模型自行决定是否规划、调用工具、spawn subagent。
- **优点：** 单轮成本低，保持当前代码路径。
- **缺点：** 无法保证“无对象不执行”“多无关候选必澄清”；没有可审计的任务状态；模型可在工具前做出未受结构约束的推断。
- **结论：** 不采用。

### 选项 C：上下文证据 + 结构化任务准入 + 状态迁移

- **做法：** 在主执行循环前增加任务准入层。它读取已有上下文证据，产出受约束的 `TurnAssessment`；代码验证该判断后，创建、更新或选择持久化的 `TaskState`，再决定澄清、直接回复、主 agent 执行或工作单元委派。
- **优点：** 将开放语义判断交给 LLM，将执行门、状态合法性、授权和并发约束交给确定性代码；可跨压缩、恢复和 provider 切换保持任务语义。
- **缺点：** 对需要行动的消息可能增加一次评估成本和延迟；需要补充状态模型、回放评测和迁移设计。
- **结论：** 采用。

## 决策

nanobot 的“意图识别”定义为**上下文优先的任务准入与状态迁移**，而不是固定分类器。

系统逻辑分为四层：

```text
上下文证据
  → TurnAssessment（本轮判断）
  → TaskState（跨轮任务事实）
  → 执行器（主 agent 或经准入的 subagent）
```

### 1. 上下文证据

复用既有会话回放、压缩摘要、运行时上下文、用户显式引用、会话提及和工作区作用域。它们只用于理解与锚定，不自动构成任务对象或操作授权。

### 2. `TurnAssessment`

LLM 以受限结构输出本轮候选判断，包括：消息行为、任务/对象锚定及证据、候选任务、任务结构、建议动作和澄清需要。它不直接获得工具执行权，且必须由代码校验。

### 3. `TaskState`

对需要跨轮、工具、多步骤、可恢复或可委派的工作，保存版本化任务状态：目标、范围、约束、验收、锚定证据、授权边界、生命周期、任务节点与 ready 前沿。模型每轮只获得相关执行前沿的受控投影。

普通闲聊或自包含回答不强制创建任务状态。

### 4. 执行与委派

只有被选中的执行前沿才能进入执行。subagent 的输入单位是已准入的 `WorkUnit`，而非模糊的“用户意图类别”；每个工作单元必须具备边界、输入、交付物、验收、资源和权限条件。

## 不变量

1. 对象缺失、任务结构缺失或多个无关系候选时：只澄清，零工具调用、零 subagent、零自主探索。
2. 唯一的活动任务帧，或关系明确的已确认任务图执行前沿：可直接推进，不重复澄清。
3. 能推进不等于有外部副作用授权；外部或不可逆动作仍经独立权限门。
4. 任何 subagent 派发必须建立在已准入工作单元上；角色标签不能代替工作边界。
5. 自动续办只保留给用户明确开启的持续目标；普通会话不得因旧上下文而无触发自行开工。

## 后果

### 正面后果

- 意图、任务、计划、授权与委派不再混为一次自由模型决策；
- 现有上下文机制继续承担其擅长的证据注入与恢复，而非被推倒重来；
- 压缩、重启和 provider 续接失效后，任务语义仍可从 `TaskState` 重建；
- 可建立“无对象零调用”“多候选必澄清”“非法状态迁移拒绝”等可回放测试。

### 代价与风险

- 行动型请求需要额外的模型判断或等价控制流程，成本与延迟须评测；
- `TaskState` 若无限增长会反过来挤占上下文，必须有大小上限、摘要和版本迁移；
- 锚定判断会有不确定性，必须保留证据、允许用户纠正，并将失败样本纳入评测；
- 任务图并发会引入资源竞争与写入冲突，不能仅依赖 subagent prompt。

## 安全与审计约束

- 所有外部输入（引用、会话提及、附件、工具结果）在进入任务评估时均视为数据，不得作为指令或授权；
- 准入决策与状态迁移应留存 task id、来源 turn、锚定证据类型、决策结果和拒绝原因；不得记录凭据或不必要的完整敏感内容；
- 任务状态投影应限长、带 schema version，并与公开聊天历史分离展示；
- 结构化评估解析失败或校验失败时，应安全降级为澄清或无工具回复，不得回退为无门禁的工具循环。

## 未决问题

本 ADR 不决定下列实现细节，须在方案或后续 ADR 中单独确认：

1. `TaskState` 的具体持久化布局：初版复用 `Session.metadata` 还是引入独立事件记录；
2. `TurnAssessment` 的调用策略：独立模型调用、主模型受限首阶段，或规则与模型的混合边界；
3. 多 ready 节点的预算、并发、写入租约、取消与结果归并；
4. 现有 `/goal`、`goal_state` 和自动续办的兼容与迁移路径；
5. WebUI 中如何呈现任务状态、澄清依据、进行中工作与用户修正入口。

## 重新审查条件

- 回放评测表明澄清率、延迟或成本无法接受；
- 真实通用任务无法由任务帧和任务图表达；
- 发现任务状态与会话/权限模型存在无法安全消解的冲突；
- 后续 ADR 对持久化或执行模型做出替代性决定。
