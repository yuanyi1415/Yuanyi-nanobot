# ADR-008：执行图桥接正确性契约

**状态：** 已接受
**日期：** 2026-08-10
**决策者：** 用户授权研发完善方案，研发负责收口
**关联需求：** FR-010 至 FR-015；AC-009、AC-012 至 AC-016
**关联决策：** ADR-004、ADR-005、ADR-006、ADR-007

## 背景

对现有 `AgentLoop`、`AgentRunner` 和 `SubagentManager` 的源码审查确认：v0.2 的方向正确，但直接把意图层塞到 build 前、把 `plan_id` 加到现有会话队列，不能安全实现。runtime 的取得和会话持久化与 build 耦合；结果投递在任务登记清理后仍可能被消费；流式终答会早于计划完成。

本决策只解决正确性与兼容性，不改变用户确认的“增量改造、沿用既有能力权限与运行机制”边界。

## 选项

### 选项 A：在现有机制上增加窄桥接适配（采用）

- `AgentLoop` 负责受限 runtime 预备、no-run 收尾、计划结果路由与终答门；
- `AgentRunner` 仅接受默认无影响的通用回调；
- `SubagentManager` 保留执行生命周期，额外保存有 TTL 的结果路由收据；
- 同会话不同计划的结果延后为任务证据，不自主生成答复。

### 选项 B：新建常驻计划调度器/任务队列

- 优点：可做全局容量预约、长任务恢复和统一队列；
- 缺点：会引入第二套生命周期、持久化和取消语义，超出本阶段增量范围。

### 选项 C：仅在 prompt 中要求模型遵守计划

- 优点：改动最少；
- 缺点：无法在消息队列、跨会话路由、流式终答和容量竞争上提供确定性保证。

## 决策

采用选项 A，并冻结以下不可绕过的契约：

1. `prepare_intent_runtime` 无副作用；`clarify`/`reply` 走受控 no-run 收尾；`ready` 才继续既有 build/run；
2. `spawn_planned` 在同一临界区分配 task id、写入 `ResultRouteReceipt`、登记后台任务；结果入队前逐字段校验有效 session、plan、node 与 task；
3. 只有同一活跃计划可回注结果；其余合法结果延后为原 TaskFrame 的完成证据，非法/重复结果隔离；
4. active plan 的必需节点未完成时，候选终答不得外发；非成功终态必须诚实说明未完成；
5. `ClarificationState` 不等同于可执行 TaskFrame；TaskFrame 跨轮持久化，ExecutionPlan 仅是切片；重规划必建新 `plan_id`，不自动使用旧计划未消费结果；
6. 并发容量竞争只允许一次安全父回退或明确 `blocked`，不引入排队器或无限重试。

## 后果

### 正面

- 结果在会话、计划和消费次数三个维度上可验证隔离；
- 不会因流式输出而向用户伪造“已完成”；
- feature flag 关闭时无新增调用/状态/协议变化；
- 后续可以通过回放测试证实，而非依赖模型“自觉”。

### 代价

- 需要新增少量 metadata、路由收据和测试夹具；
- 开启功能时，复杂任务可能多一次意图/计划模型调用；
- 第一版容量竞争的体验偏保守，不做全局排队。

## 重审条件

- 窄桥接仍需改变 Runner、memory、权限、`/goal` 或 WebUI 协议的既有语义；
- 隔离回放无法稳定做到跨会话零串扰、跨计划零误注入、终答零抢跑；
- 灰度成本或延迟不能满足后续确定的阈值。
