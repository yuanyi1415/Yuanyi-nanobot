# ADR-001：上下文优先的任务锚定

**状态：** 已接受  
**日期：** 2026-08-09  
**决策者：** 用户确认，研发负责整理  
**关联需求：** FR-002 至 FR-009；AC-001 至 AC-006

## 背景

通用 Agent 经常接收“继续”“处理一下”“按这个办”等省略表达。若系统在没有任务对象、或有多个无关候选时开始探索、调用工具或委派，就会产生无效成本、噪声、错误行动与权限风险。

nanobot 当前把普通消息直接交给主模型和工具循环，缺少独立的对象锚定与任务结构判断。

## 决策

在任何自然语言任务的规划、工具调用或 subagent 调度之前，系统必须先基于有效上下文解析执行前沿。

执行前沿可以是：

1. 一个唯一、未完成且已展示给用户的任务帧；或
2. 一个已确认任务图中，关系明确的一个或多个 ready 工作单元。

决策分支如下：

| 上下文结果 | 系统动作 |
| --- | --- |
| 没有任务对象或任务结构 | 只提出一个聚焦澄清问题；零工具调用、零 subagent、零探索。 |
| 一个唯一任务帧 | 进入任务理解与执行规划；用户“继续”等表达可续办该任务。 |
| 已确认任务图，ready 点关系明确 | 按顺序、依赖或并行关系生成推进计划。 |
| 多个彼此无关候选，或 ready 点关系未定义 | 澄清对象、优先级或关系；不自动选择。 |

对象锚定不等于外部动作授权。具有外部副作用或不可逆性的行为必须经过独立权限门。

## 理由

- 主动性应来自已知任务结构，而不是模型猜测；
- 任务图能表达多个 ready 点的合理推进，不强迫系统退化为只能做单任务；
- 停止澄清是防止盲目先行的正常行为，不是失败；
- 将对象锚定、任务理解、工作规划和调度拆开，才能审计、回放与评测委派质量。

## 后果

### 正面后果

- 可将“无对象不执行”和“多无关对象必澄清”变为可测试不变量；
- subagent 不再承担理解模糊用户指代的责任；
- 主 agent 的执行理由可解释，后续可由 WebUI 展示；
- 支持通用任务图，而非把任务限制为代码开发流水线。

### 代价与风险

- 增加一次前置状态解析以及相应延迟/成本；
- 需要定义任务帧、任务图和会话持久化，不能只改 prompt；
- 锚定错误仍可能发生，必须通过证据引用、用户更正和回放评测持续控制；
- 多 ready 工作单元的并发仍需单独做资源与写入安全设计。

## 被拒绝的方向

- 无对象时先只读侦察；
- 将普通语言简单分类为固定角色后立即派发；
- 仅依赖系统提示词要求主模型“先想再做”；
- 在全部历史或外部世界中无界搜索，以猜测“这件事”指什么。

## 重新审查条件

出现以下任一情况时，新建后续 ADR 重新审查本决策：

- 真实评测显示对象锚定造成不可接受的澄清摩擦；
- 任务图不足以表达关键通用 Agent 工作流；
- 安全或授权机制要求调整锚定与执行之间的边界；
- 会话压缩、长期记忆或多渠道统一会话使证据优先级发生冲突。
