# ADR-007：第一版实施边界与运行时兼容

**状态：** 已接受  
**日期：** 2026-08-10  
**决策者：** 用户确认，研发负责整理  
**关联需求：** FR-007、FR-008、FR-010、FR-011；AC-008 至 AC-011  
**关联决策：** ADR-004、ADR-005、ADR-006

## 背景

本项目是在用户实际使用的 nanobot 基础上做增量改造。核心风险不在于是否能新增意图识别，而在于新增逻辑意外改变已稳定的 Runner 工具循环、memory/Session 格式、subagent 生命周期、工具权限或 UI 事件，从而影响用户的日常运行。

用户确认采用如下第一版方案组合：最小 `TaskFrame`、同 runtime 的受限意图/计划调用、计划绑定 spawn、完成门、`plan_id` 精确汇合和保守并行写入规则。与此同时，要求既有运行机制不受影响。

## 决策

### 运行时兼容边界

1. 新能力以默认关闭的 feature flag 接入；关闭时完全走当前路径，不产生额外模型调用或状态写入。
2. `AgentRunner` 保持工具循环所有者；若增加通用续办回调，其默认值必须为 `None` 并严格复现当前行为。
3. 不修改 memory、Session 历史、压缩、Dream、provider 会话状态和 `/goal` 的既有数据格式或语义。
4. 不替换工具权限、账号、确认、取消、subagent 工具隔离和 WebUI 事件协议。
5. 实现和真实测试只在隔离开发库进行；用户当前运行库只接收已验证的、显式启用的版本。

### 第一版实现选择

1. `TaskFrame` 写入现有 `Session.metadata`；用户请求已足够明确时立即建立，未足够明确时只保留澄清态。
2. 意图与计划使用当前会话同一 runtime 的无业务工具结构化调用；确定性“继续”和显式引用优先不调用模型。
3. `IntentResult` 锚定失败时仅澄清；计划调用失败时产生单一 `parent` 节点，禁止自由委派。
4. 活动计划中的 subagent 必须以 `plan_node_id` 绑定；节点完成前，Runner 的通用完成门不能允许任务伪完成。
5. 每个后台任务登记 `parent_session_key` 与 `plan_id`；结果仅投递给同一有效会话，并只参与同一 `plan_id` 的汇合。
6. 并行仅适用于只读节点或明确互斥输出路径；共享写入或外部目标不明确时串行。

## 后果

### 正面后果

- 用户正在运行的默认实例不会触发新增逻辑；
- 改造面限于前置判断、计划约束和结果归属，不会变成 Runner 或 memory 重构；
- 同会话旧后台任务也不会被错误纳入新计划的汇合；
- 每一项新行为都有可关闭开关和回归验证目标。

### 代价

- 新增结构化调用会增加启用状态下部分复杂任务的延迟和成本；
- 需要为计划、任务帧和 subagent 所有权添加小型状态及回归测试；
- 第一版并行度会偏保守，优先避免写入冲突。

## 验证门

- feature flag 关闭时，现有聚焦 Runner、memory、subagent、/goal 和 WebUI 测试保持通过，且意图/计划模块调用次数为零；
- 开启后，明确任务可产出可审计计划，无对象与歧义任务零工具、零委派；
- `plan_id` 不同的同会话后台结果不能满足彼此的完成门；
- 任何跨有效 session key 的结果在进入队列、历史和模型前被拒绝；
- 关闭开关后无需迁移或清理既有会话数据，即可回到旧行为。

## 重新审查条件

- 兼容门需要修改既有 memory、Runner 或权限语义才能成立；
- feature flag 关闭仍出现新增模型调用或数据写入；
- `plan_id` 精确汇合无法通过对现有回注路径的窄扩展实现；
- 评测证明新增计划的收益不足以覆盖成本和延迟。
