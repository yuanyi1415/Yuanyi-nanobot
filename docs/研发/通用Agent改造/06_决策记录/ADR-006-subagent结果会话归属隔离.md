# ADR-006：subagent 结果的会话归属隔离

**状态：** 已接受  
**日期：** 2026-08-09  
**决策者：** 用户确认，研发负责整理  
**关联需求：** FR-010、AC-009  
**关联决策：** ADR-004、ADR-005

## 背景

subagent 的完成结果会经过消息总线回注父 agent。结果若进入错误会话，不仅会污染上下文和任务状态，还可能在不相干的用户对话中暴露内容或驱动错误执行。因此会话归属不是普通路由优化，而是主 agent 与 subagent 协作的不可突破数据边界。

当前实现会在 subagent 启动时记录 `origin.session_key`，并在公告结果时写入 `InboundMessage.session_key_override`。这为正确路由提供了基础，但仅有发布侧约定不足以抵御未来计划层、统一会话、异步清理或调用方错误带来的串线。

## 决策

1. 每个后台 subagent 在创建时捕获父会话的**有效 session key**，该键为结果唯一所有者；
2. 结果公告必须原样携带此键，并以其设置 `session_key_override`；禁止按当前活跃会话、chat ID 或模型推断重算目标；
3. `AgentLoop` 在内部 `subagent_result` 进入 pending queue、历史或模型前，必须以 `task_id` 查询任务所有权并断言目标有效键相等；
4. 未知 task、无所有权、空键或不一致消息必须隔离和可观测，不得落入任何会话或用户输出；
5. 任务所有权映射须保留到结果消费校验完成，之后才可回收；
6. 对计划节点，`parent_session_key` 由 `RequestContext` 注入，不允许 Planner、主模型或 subagent 文本指定。

## 后果

### 正面后果

- 将“结果不会串会话”从调用约定升级为双端可验证的不变量；
- 可对错误路由安全失败，而非把内容投递给“看起来最接近”的会话；
- 为并行 subagent、计划节点状态和未来 WebUI 审计提供稳定归属键。

### 代价

- `SubagentManager` 需要保留一个短生命周期的 `task_id → parent_session_key` 所有权记录；
- `AgentLoop` 需在已有回注入口增加一次常数时间校验；
- 增加跨会话、统一会话和任务清理时序的回归测试。

## 关于统一会话

本决策以“有效 session key”定义隔离边界。显式启用统一会话会将多个来源合成为同一个有效 session，属于用户主动放宽会话隔离的既有语义。

如果未来需求是“共享记忆/模型上下文，但不同聊天线程的 subagent 结果仍必须分别可见”，必须新建 `conversation_scope_id` 作为结果路由边界，并单独评审；不得把该需求伪装为本 ADR 的例外。

## 验证门

- 会话 A 发起、会话 B 活跃：B 不收到 A 的结果；
- 会话 A 发起、A 空闲、会话 B 活跃：结果仅形成 A 的内部后续处理；
- session key 被篡改、task 未知或所有权已异常清理：消息被隔离，零历史写入、零模型调用、零 outbound；
- 统一会话开启时，已有“所有来源共享同一有效 session”的语义保持显式且可测试，不得静默改变。

## 重新审查条件

- 产品确认需要跨线程共享上下文但隔离结果可见性；
- 当前 session key 无法稳定表达父会话归属；
- 双端断言导致现有合法回注路径无法兼容。
