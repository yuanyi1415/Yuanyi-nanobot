# ADR-005：意图识别与执行规划分层

**状态：** 已接受  
**日期：** 2026-08-09  
**决策者：** 用户确认，研发负责整理  
**关联需求：** FR-002、FR-005、FR-006、FR-007、FR-008、FR-009；AC-001 至 AC-008  
**关联决策：** ADR-001、ADR-002、ADR-004

## 背景

前置意图层的职责是解决“用户要什么、指向什么、是否足以推进”。Runner 的职责是解决“在当前工具、subagent 容量和运行期约束下，怎样完成已确认任务”。

若由意图层直接决定主做、串行 subagent、并行 subagent 或主子并行，它将不得不过早推断运行资源、工作依赖和交付形态；若 Runner 又自由重做意图理解，则会回到当前主 agent 临场猜测是否委派的问题。

## 选项

### 选项 A：意图层同时决定执行组织

- **优点：** 只有一个结构化前置输出。
- **缺点：** 混淆用户语义与运行期规划；执行方式容易在缺少工具、容量和依赖事实时被过早拍板。
- **结论：** 不采用。

### 选项 B：Runner 不接收结构化意图，自由理解并执行

- **优点：** 最接近当前代码。
- **缺点：** 主 agent 仍可能无对象先行，且是否拆分 subagent 继续依赖临场提示词判断。
- **结论：** 不采用。

### 选项 C：意图层输出 `IntentResult`，Runner 输出 `ExecutionPlan`

- **优点：** 语义锚定与执行规划各自拥有唯一职责；Runner 可在已确认范围内按真实运行条件规划工作；保留 nanobot 当前执行核心。
- **缺点：** 新增一个短生命周期执行图和其最小协调桥接；需验证与现有后台 subagent 回注的汇合时机。
- **结论：** 采用。

## 决策

### 意图层：`IntentResult`

意图层无工具运行，仅产生：

- 用户行为：问答、新任务、续办、修正或澄清回答；
- 任务/对象锚定结果：无、唯一或歧义；
- 目标、范围、约束和验收要求；
- 有效上下文证据引用；
- 动作分支：回复、澄清或可交给 Runner 推进。

它不得包含执行者分配、subagent 数量、工具调用顺序或串并行判断。

### Runner：`ExecutionPlan`

当且仅当 `IntentResult` 表示可推进任务时，Runner 在业务工具调用前生成执行图。执行图是本轮短生命周期工作 DAG：

```text
节点 = 工作目标 + 输入 + 交付物 + 验收 + 执行者(parent/subagent)
边   = 必须完成后才能开始的依赖
```

执行线不是固定类别，而是该图的自然投影：

| 执行图 | 对应执行线 |
| --- | --- |
| 单一 `parent` 节点 | 主 agent 独立执行 |
| 一条依赖链上的 `subagent` 节点 | 子 agent 串行 |
| 无依赖的多个 `subagent` 节点 | 子 agent 并行 |
| 独立的 `parent` 与 `subagent` 节点，随后汇合 | 主 agent 与子 agent 并行 |

任务图与执行图不可混淆：任务图是用户任务跨轮关系；执行图是 Runner 为当前一轮或当前执行切片临时生成的运行安排。

### 既有运行机制的消费

- `parent` 节点：继续由现有 `AgentRunner` 模型—工具循环执行；
- 串行 `subagent` 节点：复用现有 `spawn(wait=true)` 与结果回注；
- 并行 `subagent` 节点：复用既有后台 spawn、并发上限、生命周期事件和结果回注；
- 汇合节点：在声明的依赖结果抵达前，不得将任务标记为完成；由最小协调桥接等待和投递现有回注结果，再交还主 agent 整合。

该桥接只把执行图翻译为现有调用路径，不重写 `AgentRunner`、`SubagentManager`、工具权限、取消机制或 WebUI 事件协议。

## 后果

### 正面后果

- 主 agent 不必从模糊用户话语中猜测是否拆分；
- 允许真正的主子混合并行，而非被静态角色限制；
- 可以用依赖关系审计每个 subagent 为什么被派发、何时汇合；
- 保持 nanobot 现有工具循环和 subagent 管理优势。

### 代价与风险

- 需要定义执行图的最小 schema 与计划失败时的降级；
- 当前后台 subagent 结果可能晚于主 agent 的首次回复，汇合控制必须额外验证；
- 执行图若过度细化，会制造不必要的规划和模型成本。

## 未决问题

1. `ExecutionPlan` 由 Runner 的独立无工具计划调用生成，还是由受限的首个 Runner 迭代生成；
2. 并行节点的同轮等待、超时、部分失败和提前汇合策略；
3. 执行图是否仅驻留内存，还是在需要恢复的长任务中写入现有 session metadata；
4. 与现有 `/goal` 自动续办和 `max_iterations` 切片的精确衔接；
5. 计划生成和汇合桥接的回放指标、额外延迟与成本阈值。

## 重新审查条件

- 执行图无法经最小桥接可靠映射到现有 Runner/subagent 调用；
- 额外规划造成不可接受的延迟或成本；
- 回放评测显示执行图并未减少错误委派或无效主 agent 工作。
