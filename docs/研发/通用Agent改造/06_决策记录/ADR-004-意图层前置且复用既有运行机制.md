# ADR-004：意图层前置且复用既有运行机制

**状态：** 部分被 ADR-005 替代  
**日期：** 2026-08-09  
**决策者：** 用户确认，研发负责整理  
**关联需求：** FR-001 至 FR-009；AC-001 至 AC-007  
**关联决策：** ADR-001、ADR-002；收紧 ADR-003 的实现范围；执行职责见 ADR-005

## 背景

nanobot 已具备成熟的消息循环、主 agent 工具循环、subagent 管理、串并行工具执行、结果回注、取消、生命周期事件和能力权限机制。本项目要解决的是这些机制启动前没有可靠的任务理解与委派依据，而不是替换它们。

若把任务状态、权限和执行调度全部另起炉灶，会扩大改造面，破坏现有稳定行为，也增加与用户本地运行实例不兼容的风险。

## 决策

新增一个无工具的**意图层**，置于现有普通消息运行机制之前。它读取有效上下文，产出受校验的 `IntentContext`；随后由既有 nanobot 运行机制消费该输入。

> **替代说明：** 本 ADR 原先将执行组织放入 `IntentContext`。该部分已由 ADR-005 替代：意图层只输出 `IntentResult`，执行组织由 Runner 生成 `ExecutionPlan`。

```text
现有：restore → compact → command → build → run → save → respond

改造后：restore → compact → command → recognize_intent
       → build（附带 IntentContext）→ run（现有机制）→ save → respond
```

`IntentContext` 只描述：

- 当前任务或任务图执行前沿的锚定结果与证据引用；
- 本轮动作：直接回复、澄清、执行；
- 执行组织：主 agent、串行 subagent 工作单元、并行 subagent 工作单元；
- 交付范围、约束、验收及必要的结果归并说明。

它不包含工具权限判断、账号策略、工具调用细节或新的执行引擎定义。

## 消费方式

| 意图层输出 | 既有机制的消费方式 |
| --- | --- |
| `clarify` | 直接返回澄清文本；不启动 Runner、工具或 subagent。 |
| `reply` | 直接返回无工具回复，或交给既有主 agent 生成回复。 |
| `main` | 将 `IntentContext` 作为受控运行时上下文注入，交给现有 `AgentRunner` 与工具循环执行。 |
| `subagent_serial` | 使用既有 `SubagentManager` 按工作单元顺序执行；结果仍通过既有回注/主 agent 归并路径处理。 |
| `subagent_parallel` | 使用既有 `SubagentManager` 并发执行已声明独立的工作单元；取消、结果预算和回注仍由既有机制处理。 |

实现中允许为上述输入增加一个小型桥接层，但不得重写 `AgentRunner`、工具权限检查、subagent 生命周期、结果事件协议或工作区安全边界。

## 不在范围内

- 新建统一能力权限、账号授权或确认策略；
- 替换当前工具注册、调用、并发和错误处理机制；
- 替换当前 subagent 结果持久化、取消或 WebUI 生命周期；
- 引入独立任务执行服务、队列或数据库。

## 后果

### 正面后果

- 改造集中在任务理解与执行组织，复用现有已验证运行路径；
- 主 agent 不再从零判断是否该委派，但仍保留既有执行和整合能力；
- 权限行为保持用户当前本地 nanobot 的实际语义；
- 可先以最小增量验证“无对象不运行”和“明确任务可组织 subagent”。

### 代价与风险

- 现有运行机制未必天然支持接收预先规划的串/并行 subagent 工作单元，需要小型适配；
- 若仅把执行组织写进 prompt 而不做桥接，主 agent 仍可能忽略或重新判断，因此必须验证消费是否具备约束力；
- `IntentContext` 过大或过度细化会增加提示成本，需保持为紧凑、可追溯输入。

## 重新审查条件

- 最小桥接层无法可靠驱动既有 subagent 机制；
- 复用现有权限语义无法表达意图层所需的任务范围；
- 回放评测显示前置输入无法降低主 agent 的无效探索或错误委派。
