# 项目目标与范围

**版本：** v0.2  
**状态：** 已确认的当前阶段边界  
**更新日期：** 2026-08-09

**本次变更：** 明确本项目是对 nanobot 的增量改造，优先保留已有运行优势，不以本项目名义重构成熟运行机制。

## 项目目标

将 nanobot 演进为通用型 Agent：它能在对话、研究、规划、内容处理、外部工具操作、长期任务与代码任务等场景中，先基于有效上下文理解当前可推进对象，再决定回答、澄清、规划、执行或委派 subagent。

当前阶段聚焦于：定义“上下文优先的意图理解与任务调度”产品规则，消除主 agent 在用户任务尚未成立时盲目执行或盲目委派的行为。

## 增量改造原则

本项目不是重写 nanobot 的 Agent 框架。每一项设计和实现必须同时回答：

1. **保留什么：** 现有消息循环、上下文构建与压缩、`AgentRunner` 工具循环、工具注册与权限、`SubagentManager` 生命周期、结果回注和 WebUI 事件等已验证能力；
2. **只补什么：** 在普通消息进入既有运行机制前，补充基于上下文的意图识别与执行组织输入；
3. **明确不动什么：** 不因本主题重写 Runner、权限、工具系统、subagent 生命周期或工作区安全边界；
4. **如何证明没有伤害：** 每个实现切片必须列出现有回归测试和新增行为回放，确认旧路径仍按原语义工作。

若某项需求确实无法通过最小桥接实现，必须先给出代码证据、替代方案和影响评估，再由用户决定是否扩大范围。

## 成功标准

- 没有可解析任务对象时，nanobot 不调用工具、不创建计划、不派发 subagent，只提出一个聚焦澄清问题；
- 唯一任务或关系明确的任务图存在时，nanobot 能基于该结构继续推进；
- 多个彼此无关或关系未定义的候选点存在时，nanobot 停止并澄清；
- subagent 调度发生在任务理解、工作规划与安全准入之后，而非由主模型临场猜测；
- 所有后续实现可由需求、ADR、评测场景和代码变更相互追溯。
- 所有改动都以保留既有运行优势为前提，改造范围不得扩张为框架重构。

## 本阶段范围

### 包含

- 当前 nanobot 意图相关机制的源码取证；
- 任务对象锚定、任务图和执行前沿的产品规则；
- subagent 调度前置条件；
- 需求、方案、评测和实施资料的治理方式。

### 不包含

- 直接修改运行中的本地 nanobot；
- 在未完成架构与评测设计前实现新调度器；
- 固化 subagent 的数量或静态角色；
- 未经用户确认的外部操作权限策略；
- 将本私有研发资料同步回上游开源仓库。

## 约束

- 当前工作目录是用户正在使用的 nanobot；任何运行时配置、服务启停或功能实验都需与隔离开发环境分离；
- 当前问题应服务通用 Agent，不局限于代码开发；
- 不得把模型推测当作任务对象、用户授权或验收标准；
- 代码、调研和实施事实与用户确认的产品规则发生冲突时，记录冲突并请求决策，不静默选择。
